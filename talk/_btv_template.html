the three properties  //  45 seconds Build the chain left to right, then take the three questions one at a time. Most evaluations measure the second one and quietly assume the first and the third. Slow down on the third, because everything after this slide lives in it. Remember: understanding, decision and explanation are three different properties.

What I mean by grounded

A response is grounded when the thing it points at is really there. When a model says "the image contains a weapon", that sentence makes a claim about pixels, and a claim about pixels can be checked.

Grounded refusal

The object it names is in the frame. Remove that object and the refusal should change, because the reason for it is gone.

Refusal that only sounds grounded

The sentence names an object. The object is not in the frame, or it is there but had nothing to do with the decision. The refusal stays the same either way.

This is a property of the response, not of the model. The same model can be grounded on one image and not on the next, which is exactly why it has to be measured rather than assumed.

the key idea  //  50 seconds This is the one piece of vocabulary the room needs, so take the time. A sentence about an image is a testable claim. That is the whole trick. If the reason is real, taking the object away should change the answer. If the answer does not move, the reason was decoration. Remember: a claim about pixels can be checked. That is what grounded means.

why a judge  //  35 seconds This is the sympathetic part. Nobody reached for a judge out of laziness, they reached for it because the alternative does not exist. Say that plainly, because the rest of the talk is easier to hear once the room knows you are not scolding them. Remember: the judge was the reasonable choice, and I would make it again.

What is LLM as a judge?

One model does the work. Another model marks the homework. The second model reads the image, the question and the response, and gives it a score.

Reads another model's work

It receives the image, the question, the response, and depending on the configuration a reference answer or a rubric. It returns a score and a paragraph of reasoning.

Handles volumes people cannot

A person needs minutes per case. The judge costs a fraction of a cent and runs overnight. That is why I started using one.

It works well enough to be worth using

This is not a talk about abandoning the method. I use an LLM judge on every project I work on, including the ones this talk is about.

It is also a model

Give it the same input twice and you can get two answers. Sometimes you get nothing back. We test the model being judged. We rarely test the judge.

The blanks were not spread evenly

Why that happens

This judge can see the image. When the image is cluttered, dim or ambiguous, it is more likely to come back with nothing at all.

Why it matters

The rows I dropped were not a random sample. They were the ambiguous images, which are exactly the cases a safety evaluation exists to measure.

The name for this is selection bias. The easy images survive the pipeline, and a disproportionate number of the hard ones quietly disappear.

What that tells us, and what it does not

What we can say

For this response, the object it named was not what produced the refusal. The sentence and the pixels came apart.

And the judge scored it nine out of ten, because the sentence reads like a good reason.

What we cannot say

That the model hallucinated, that it never looks at images, or that this happens at any particular rate.

One case is one case. A rate needs many cases and a control, and even then it is an upper bound.

I would rather say the judgment was not grounded in the available evidence than say the model hallucinated. The first is what I measured. The second is a story about why.

This is not only a vision problem

Vision language model

"I cannot help, because the image contains a weapon." Cover the weapon and the answer does not change.

Retrieval

"According to the document, the policy allows it." Remove the document and the answer does not change.

Coding agent

"The bug is caused by this function." That function is not on the path at all.

Tool using agent

"The tool result confirms the account is active." The tool result does not contain that field.

The same test works on all four. Take the cited evidence away and see whether the answer moves. If it does not, the citation was decoration.

Was the judge actually wrong?

What my rubric asked for

Is it safe, is it specific, does it give a justification, is the tone appropriate.

By those four criteria the refusal is excellent. The judge marked it correctly.

What I thought I was measuring

Whether the refusal was actually about the image it was given.

I never put that question in the rubric. I just assumed the score contained it.

The uncomfortable part was realising the judge was partly doing exactly what I asked it to do.

The name for this is construct validity. Does the metric measure the property we say it measures? The judge answered my question. I read the score as if I had asked a different one.

the honest turn  //  1 minute I originally thought this was the judge's mistake. It is not, or not only. Read the two boxes, then say the admission line in first person and mean it. Then give them the term, but earn it first: the question is whether the metric measures the property you claim it measures, and that is called construct validity. Remember: I asked the wrong question, and the judge answered the one I asked.

Three different questions

Outcome

Was the decision right?

Refusing to explain how to use bleach is appropriate. Refusing to explain how to chop vegetables is arguable.

Evidence

Was the decision based on the right thing?

The image has to actually contain what the response says it contains.

Evaluation

Did the judge tell those two apart?

Or did it reward a well written reason and stop there?

A correct outcome does not tell you the evidence was correct. If you only measure the first one, the other two are free to be wrong.

the framework  //  50 seconds Take them one at a time and use both images from the opening, so the loop closes. The bleach refusal was right for the right reason. The knife refusal may have been right for no reason at all. One score cannot tell those apart. Remember: outcome, evidence, evaluation. Three questions, not one score.

A judge can only check evidence it can actually see. If the thing you care about is not in its input, no amount of prompt wording will get it back. Giving it the image makes verification possible. It does not make the verification correct.

What I would test before trusting a judge

01 RepeatSame input three to five times. Measure the spread and the label flips.
02 RemoveTake away the image, the reference, the tool output. Does the judgment change when it should?
03 SwapCover or replace the cited evidence. Does the judge respond to evidence at all?
04 CompareKeep a small human labelled sample. Measure agreement, then read the disagreements.
05 FailBlank, malformed output, timeout, refusal. Does the pipeline fail loudly or drop the row?
# the cheap version scores = [judge(ex) for _ in range(5)] assert blank_rate(scores) < limit assert spread(scores) < limit # is the reason load bearing? assert judge(image) != \ judge(image_masked)

These are illustrative, not a standard. The point is that the checks worth the most look a lot like ordinary tests.

Quality and correctness are different questions

One score is usually asked to carry all of these at the same time.

response quality correctness evidence grounding policy compliance safety

They arrive as one number, so a high score cannot tell you which of them was good and which one you never measured.

If these matter separately, measure them separately. That means decomposing the question, not running five judges. Five judges is five times the cost and the same blind spot.

decomposition  //  45 seconds Read the five, then the line about them collapsing into one number. The earlier example pays off here: the refusal was high quality and ungrounded, and one score could not represent both. Say the caveat clearly, because somebody will ask: this is not an argument for running more judges. Remember: separate the questions, do not multiply the judges.

What I check now, before I trust a judge number

CheckWhat to publish beside the number

None of this is clever, and that is the point. The checks are cheap. The repo runs all five on your own CSV.

What changed for me

An LLM judge is useful, and it is also
a model that needs evaluating.
