How would I check that?

When a model says "the image contains a weapon", that sentence makes a claim about pixels. Claims about pixels can be tested. If that reason is really doing the work, then taking the object out of the image should change the answer.

If the reason is load bearing

Remove the object it named, ask the identical question, and the answer should move, because the reason for it is gone.

If it is not

The answer stays exactly the same, and the sentence about the image turns out to be harder to verify than it looked.

Keep this test in mind. It is the only idea in the talk I use twice, first on the model, and later on the thing that scores the model.

What is LLM as a judge?

One model does the work. Another model evaluates the result. The second model reads the image, the question and the response, and returns a score.

It scales

A person needs minutes per case. The judge costs a fraction of a cent and runs overnight, which is the only reason the evaluation happens at all.

It is flexible

It works on open ended responses, where there is no single correct string to match against.

It works well enough to be worth using

This is not a talk about abandoning the method. I use an LLM judge on every project I work on, including this one.

It is also a model

Which means everything we already know about models applies to it as well. We test the model being judged. We rarely test the judge.

What that tells us, and what it does not

What we can say

In this example, the response did not move when the evidence it cited was removed, and the control patch did not move it either.

So the model's stated visual reason is difficult to verify as load bearing, and the judge scored the response nine out of ten anyway.

What we cannot say

That the model ignored the image, that it hallucinated, or that this happens at any particular rate.

A model may be using redundant cues, surrounding context, or features that correlate with the object. Covering it is evidence about whether the stated reason is load bearing. It is not proof about what happened inside the model.

Everything on this slide is about the model. The same test comes back later, pointed at the judge.

Five tests I run before I trust a judge

RepeatCan I reproduce the measurement? Run the same case several times and look at the spread, the label flips, and whether the conclusion changes.
PerturbDoes the judgment respond to evidence that should matter? Decide the expected behaviour first, then remove, cover or swap the evidence.
CountWhat failed to become a measurement at all? Blanks, malformed output, parse failures, timeouts, filtered responses.
CompareHow does this line up with people? Keep a small human labelled sample, and read the disagreements rather than only the agreement number.
SeparateAm I asking one score to carry several properties? Quality, correctness, grounding, safety and policy are not one thing.
# a perturbation is only a test # if I write down what I expect before = judge(original) after = judge(counterfactual) inspect_delta( before, after, expectation, )

The expected behaviour depends on the task, so this is not a universal assertion. The part that matters is writing the expectation down before running the test.

What changed for me

An LLM judge is useful, and it is also
a model that needs evaluating.

Treat the judge as part of the system under test, not as ground truth outside it.
